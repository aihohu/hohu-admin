# AI 安全边界

面向部署者和 AI 工具贡献者。AI 默认启用，但登录成功不等于获得 Agent、模型或工具访问权。

## 权限与数据访问

AI 入口使用显式权限；Agent 使用 Role-Agent 绑定，模型使用租户模型策略，工具使用精确的功能权限及数据范围。`shared` 标记和超级管理员角色不是 Agent/Tool 的通用授权旁路。

角色管理的「AI Agent 授权」读取 `GET /ai/role-agent/{roleId}`，展示可授权 Agent、当前绑定、`ai:chat:use` 入口权限，以及各 Agent 中模型可见工具声明的功能权限。工具状态按当前角色已授权的菜单权限和部署工具开关计算；用户实际使用时还会合并其其他启用角色的权限，并检查 Agent 绑定、租户模型策略与数据范围。因此页面状态用于定位配置缺口，不是用户最终可执行性的保证。勾选 Agent 只更新 Role-Agent 绑定；缺少的菜单权限仍需在角色的「菜单授权」中单独配置。

Gateway 在执行前检查 tenant、owner、当前授权和工具声明。历史消息、工具结果、文件及跨轮引用也需按当前权限重新投影，不能因为曾经显示过就永久可访问。后端拒绝是授权依据，Prompt 或前端隐藏不能替代授权。

`user.create` 要求 `system:user:add`；仅在指定部门时额外要求 `system:dept:list`，并校验部门属于当前租户、处于启用状态且在操作者数据范围内。`primary_dept_id` 可省略或为 `null`：当前租户关闭 `user_require_primary_dept` 时允许不分配部门，开启时返回 `USER_PRIMARY_DEPT_REQUIRED`。预检和确认后的执行均检查设置，最终写入复用用户管理页面的角色与部门授权服务；不分配部门不跳过默认角色的授权上界校验。用户名预检与实际创建均在当前租户内查重，其他租户的同名用户不构成冲突。`user.count` 同时限定可信租户和当前操作者的行范围。创建仍需人工确认，密码不进入模型或结果。

## 系统级 AI 管理

系统 Agent、Provider/模型目录和租户模型策略管理统一使用普通用户登录会话。系统超级管理员必须是默认租户中启用的账号，并绑定默认租户中启用的 `R_SUPER` 角色；用户名不授予权限。其他租户的管理员不得操作这些全局资源。

「AI 管理 → 模型管理」（`/ai/provider`）的动态菜单和路由按同一系统角色生成，后端仍在每次请求重新认证和授权。`/platform/ai/providers` 及其模型、连通性测试子路径接受普通系统超级管理员 access token；`/platform` 路径前缀不表示需要第二次登录。独立平台 token 对这些接口无效，其他独立平台运维接口按各自认证边界处理。

全局配置管理权不自动授予模型使用权或 Agent/Tool 执行权。Provider 和模型目录保持全局作用域，租户可使用哪些模型仍由租户模型策略决定；Agent 与工具使用授权继续遵循上节规则。

系统级管理请求必须提供 `X-Platform-Reason`、`X-Platform-Ticket` 和 `X-Correlation-ID`。已认证但没有系统管理权时返回 HTTP 403 和 `SYSTEM_ADMIN_ONLY`；缺少审计上下文时返回 HTTP 400 和 `PLATFORM_AUDIT_CONTEXT_REQUIRED`，不执行相应业务。授权意图独立持久化，成功操作的完成审计与配置写入使用同一事务；审计持久化失败时拒绝操作。审计记录真实用户及其租户、操作原因、工单和关联 ID，不记录提示词正文或密钥。维护客户端约束见 [AI 运维](AI-OPERATIONS.md)。

## 执行与人工确认

破坏性操作、声明必须确认的工具和相应风险检测结果进入人工确认。Gateway 绑定确认对象、参数、执行身份与业务快照，并在批准后复验授权和有效状态，防止换参、重复执行和撤权后继续执行。

确认编排由 Gateway 控制。直接调用和预览后确认使用持久化的 `PreparedAction`；两阶段工具的执行入口不向模型开放。模型可以表达预览或执行意图，但模型话术、Markdown 和提示词不构成批准。批准只能来自经认证客户端的确认请求，不能在批准时替换执行工具、业务参数或预览快照。

同一个 action 最多进入一次执行，拒绝、过期或已结束的动作不能恢复执行。批准及真正执行前重新检查 owner、可信租户、用户状态、当前权限、数据范围和业务快照，避免撤权后执行或重复副作用。确认只针对一次完整工具操作，不提供逐行勾选、多级审批或通用工作流。

当前工具使用请求内执行路径；人工确认只代表批准，不承诺后台任务在客户端断线或服务重启后继续执行。超过同步上限的请求显式拒绝，使用者需分批处理。未来的队列、持久任务及进度协议需要独立交付，不能从确认成功推断已经具备这些能力。

`user.batch_delete` 的确认卡展示完整用户名与 ID 名单，并绑定预检解析出的精确 ID 集合及身份快照。完整名单超过单个确认字段的 256 字符上限时，预检拒绝并提示缩小范围、分批删除，不使用截断名单批准全部目标。`job.update_cron` 的确认卡展示任务名称、绑定的任务 ID、新 cron 及旧值到新值的摘要；确认不会修改冻结参数。展示详情中的大整数 ID 使用字符串传输，避免浏览器丢失精度。任务状态变更仍按现有调度服务规则处理，确认摘要不构成旧 cron 的并发版本锁。

`job.update_cron` 的持久确认和执行结果都绑定同一个任务 ID。批准及历史结果读取会复核当前 agent 访问权、`system:job:edit` 显式权限，并通过任务服务确认目标仍属于当前租户且注册为租户任务；跨租户、平台任务、未注册或已删除任务均拒绝访问。

`ai_operation_log` 记录工具执行事实；历史消息卡片和流式事件是展示投影，不能代替授权或副作用判断。创建批次、文件等持久资源的预览不能仅因名称为“预览”而声明只读；自动重放必须符合经审计的幂等契约。

经持久确认执行的同库写工具（部门、角色、用户管理及任务 cron 更新）将业务修改、确认成功状态和必需操作审计放在同一数据库事务中。必需审计写入失败、完成状态条件更新失败或工具返回业务失败时，业务修改回滚；聊天显示或 Redis 辅助通知失败不能把已提交成功改写为业务失败。重复确认读取已核验的完成事实，不再次执行工具。

新执行路径无法确认提交结果时，确认接口保留 `running`，提示结果待核对；流式执行使用 `AI_EXECUTION_OUTCOME_UNKNOWN` 结束本轮，不把它当作普通工具失败继续执行。此时请刷新会话或联系管理员核对，不要重新办理。文件存储不属于数据库事务；上述同库保证不代表文件操作、历史记录或跨新确认请求已经具备完整恢复与去重能力。

确认、恢复流和后台清理会从主库核对同一个确认对象。对于具备完整执行身份和绑定证据的同库写操作，核对持有原执行所需的上下文锁，只有确认原事务已结束、原执行租约已到期，或原执行方正在核对自己的不明提交时，才可将未完成操作围栏为失败；旧执行方随后无法继续执行。正常有效租约不被重复确认抢占。主库不可达、锁超时、绑定损坏，以及不能证明外部副作用的文件操作仍保持待核对，不根据 Redis 过期或连接断开推断业务失败。核对本身不重新调用业务工具。

会话软删除或源消息失效不抹掉已提交的完成事实，也不允许重新执行。恢复流优先读取持久记录，Redis 缺失或故障不会把已有执行记录变成可重办的过期确认；未知结果的说明可补入已有聊天内容。迟到的流、通用日志更新和消息收尾不能覆盖已核验的完成结果。显示补写失败时，业务事实保持不变。

操作轮询、Trace 和历史消息对受保护的写操作使用同一完成证据规则；缺日志、缺确认对象或状态绑定不一致时显示待核对，不展示未经核验的成功或失败。取消、过期标签也需要证明操作从未开始，才能解除同会话办理限制。明确注册为只读且没有写协议标记的工具保留原人工确认语义，不能凭记录中的只读标签豁免写操作保护。

用户单删、批删及 AI 用户批删会先按统一顺序锁定目标用户的会话、源消息、确认对象和审计，再锁目标用户并复查依赖。未确认、执行中、旧协议无法证明终态或绑定损坏的依赖会阻止硬删除，避免级联删除核对证据；会话软删除也会保护未决执行。依赖在两次检查之间变化时，入口最多整体回滚并重建一次删除计划，重新检查当前权限，且不重复业务 handler。该并发保证要求 PostgreSQL `READ COMMITTED`；其他事务隔离级别拒绝此删除路径，不自动更改数据库配置。

删除目标不再可见时，历史消息可返回经当前权限和成功审计核验的安全回执。`completedToolCallIds` 仅包含该用户在同租户、同会话、同 trace 下已成功的删除调用 ID，不包含已删除目标、原参数或结果。客户端据此核对本轮完成状态，不将安全裁剪误报为卡片同步失败。

在 `memory` 模式下，刷新后恢复已持久化确认的流会观察数据库中的终态，保留原到期时间，不依赖旧连接的内存等待对象。恢复流不执行工具；批准仍由确认接口复核权限并执行，断流、取消等待或恢复不会构成批准。

工具开发需区分只读、幂等和实际副作用；输出经统一脱敏，面向客户端的展示数据不应无条件塞入模型上下文。运行 `uv run python -m tools.checks.check_ai_tools` 检查内置工具接入规则。

## 账号导入校验

账号导入的 CSV/Excel 解析复用 `app/utils/validators.py` 中的用户名校验，与注册和管理员创建/更新保持一致：2–16 位字母或数字（包括中文），不接受下划线、标点或内部空格。导入保留单元格首尾空白规范化，非法用户名按原行号返回 `AI_IMPORT_USERNAME_INVALID`，不进入后续写入。此校验不迁移或重命名已存在的账号。

文件解析和业务预览不构成写入批准。导入执行仍由持久确认绑定文件、预览快照和冻结参数，批准时重新检查当前用户、租户及授权；格式有效不能替代角色和部门授权检查。

## 文件与 Provider

私有附件及导出结果按 tenant/owner 鉴权。扩展名、MIME、解析资源预算、路径和所有权共同约束文件访问；上传成功不表示可以公开读取或被任意工具使用。

Provider 连接走统一 [出站控制](../app/modules/ai/core/provider_egress.py)，包括允许列表、DNS/IP 验证、超时、响应大小、并发与重试边界。恶意输入检测不能证明 Prompt 注入已被完全解决；权限、数据范围和执行确认始终需要独立生效。

Provider 密钥只通过创建或更新入参接收，响应以 `credentialConfigured` 表示配置状态，不返回原始或加密密钥。连通性测试使用已保存的 Provider 和所属模型配置，仍需系统管理权限、审计上下文和出站校验；持有管理角色不能绕过连接限制。

## 紧急停用

将部署配置 `AI_MODULE_ENABLED=false` 后重启服务。关闭时 AI 业务组件不初始化，`/ai/**` 与 `/platform/ai/**` 返回 HTTP 503 和 `AI_MODULE_DISABLED`；核查非 AI 功能仍正常。

该开关是部署熔断，不是日常用户授权方式。恢复前定位问题、撤销受影响凭据或权限，并验证拒绝路径。漏洞报告统一遵循 [安全说明](SECURITY.md)。
