# 后端测试指南

测试代码放在 `tests/`，部署初始化放在 `scripts/`，运维工具放在 `tools/`。不要用生产数据库或共享开发数据库跑测试。

## 环境与命令

在后端仓库执行 `uv sync --all-extras --dev`。测试服务配置以 [.env.test](../.env.test) 和 [CI 工作流](../.github/workflows/ci.yml) 为参考；先确认数据库、Redis 地址及命名空间属于专用测试环境，再执行迁移和测试。`ENV=test` 本身不能把一个生产 DATABASE_URL 变安全。

```bash
uv run pytest tests/test_main.py
uv run ruff check .
uv run ruff format --check .
uv run pytest --cov=app --cov-report=term-missing --cov-fail-under=70
uv run python -m tools.checks.check_ai_tools
uv run python -m tools.checks.check_docs
```

## 执行时机

| 阶段 | 检查要求 |
| --- | --- |
| 范围冻结前 | 建立下文完整用户操作矩阵；识别凭据/网络前提和真实驱动风险 |
| 首个可运行候选及功能合入前 | 在隔离环境完成适用用户旅程；不能推迟到发布末期人工手测 |
| 开发过程中 | 按 TDD 运行新增或修改行为的相关回归测试 |
| 每次 commit | pre-commit 执行 Ruff lint、格式检查、AI 工具静态检查、公开文档检查 |
| 功能完成、交付验收 | 在隔离环境执行全量 pytest，覆盖率至少 70% |
| CI | 执行全量测试、Python 版本矩阵、覆盖率门禁和发布资格验收 |

[pre-commit 配置](../.pre-commit-config.yaml) 不自动运行 pytest，也不将全量测试转移到 pre-push。保留的四项检查无需启动 PostgreSQL 或 Redis；相关测试和全量验收仍须遵守测试环境隔离要求。纯文档修正按 [开发指南](DEV-GUIDELINES.md) 验证。

## 完整用户操作验收

范围确定时写出矩阵、非目标和预期；首个可运行候选就执行，行为变化后重跑受影响旅程，冻结与正式镜像阶段再复验。UI、API 和持久状态共同断言，不能用单元覆盖率、测试数量或一次成功截图替代完整操作。纯文档变更注明不适用，不虚构业务验收。

| 用户旅程 | 必须观察 |
| --- | --- |
| 登录及退出 | 正确/错误凭据、权限边界、退出后旧 access/refresh 不可用 |
| 权限 | 可用角色的正常操作；无权限角色的页面和直接 API 拒绝；跨租户/撤权边界及零越权写入 |
| 文件 | 合法上传、预览/下载字节一致、禁止类型/超限拒绝、私有资源的归属限制及删除后的状态；区分公开与私有文件 |
| AI 批准 | 真实确认、重复确认仅执行一次、业务结果与卡片一致、同会话继续、刷新/详情恢复 |
| AI 取消与预检拒绝 | 分别验证取消和可证明未执行业务的拒绝；业务零写入、准确提示、原会话下一请求成功且被持久化 |
| AI 撤权/执行未知 | 确认前撤权拒绝；ACK 丢失与重启后依事实恢复，不自动重放未知动作，不以改为失败解除阻塞 |

先用确定性请求/夹具覆盖状态闭环，再用真实 Provider 和浏览器做少量完整旅程。模型可能避开重复调用或要求澄清，不能只匹配提示文本就声称走过拒绝路径；同时核对实际工具、错误码、执行次数和持久化记录。模型叙述与工具状态不一致时单列观察项，不能仅凭模型回答判断业务成功。

凭据和网络检查的执行时点、失效条件及阻断规则统一见 [发布维护](RELEASE.md#前置检查与复核时点)。涉及事务协议时，在方案大规模实现前使用真实驱动验证提交前断链、提交后静默 ACK 和请求取消的资源释放，再扩展完整工具矩阵。

同版本结果复用必须注明实际测试环境及部署方确认来源。相同版本号本身不足以证明镜像一致；核对 digest、平台与配置差异。部署方声明与代理直接实测分别记录，目标主机网络、凭据、持久卷和恢复条件不能凭本地通过而标记为现场实测。

## 回归设计

账号导入测试应覆盖格式拒绝、原行号错误返回及拒绝后的零写入，并核对注册、管理员操作与导入使用同一校验规则。业务校验与执行授权边界见 [AI 安全手册](AI-SECURITY.md#账号导入校验)。

- 纯业务规则优先单元测试；SQL 查询、约束和事务行为使用真实 PostgreSQL 集成测试。
- 数据库测试复用事务回滚 fixture；自行建立的表、文件和 Redis 键由测试清理。不要假定执行顺序或依赖上个测试的数据。
- 排序断言使用明确的 ID、版本或业务排序键，不依赖恰好不同的创建时间。
- API 同时覆盖成功、参数拒绝、无权限、跨租户、禁用状态及异常回滚。
- 涉及撤权、幂等或并发时测试实际竞态；涉及迁移时验证空库、支持的升级边界和数据保留。
- Mock Provider 测试只能证明受控输入下的行为，不能代替真实 Provider、浏览器或 Docker 部署验证。

子进程不继承父进程的 pytest monkeypatch。涉及子进程的单元测试必须在新进程内隔离外部依赖；例如 [AI 停用测试](../tests/modules/ai/test_module_disabled.py) 在子进程模拟限流依赖并禁止异步网络连接，无需启动 PostgreSQL 或 Redis，仍须校验 `AI_MODULE_DISABLED` 和 AI 业务模块未加载。

## CI 与发布验证

AI 工具静态检查包含 `direct_confirmation_fields_declared` 警告：模型可见的直接调用写工具需要确认、含业务参数却未声明 `args_summary_fields` 时提示开发者补充安全的参数展示；只读、无业务参数和两阶段确认流程不受此项检查影响。只有 warning 时命令仍返回 0，其他 error 仍阻断。该检查不执行预演，也不能代替对确认字段的业务完整性、冻结值绑定、翻译和时区的实际验收。

当前 CI 在 Python 3.12、3.13、3.14 上运行测试，服务使用 PostgreSQL 15 和 Redis 7，覆盖率门槛为 70%。具体命令以工作流为准；不要在手册维护易过期的“最新测试通过数量”。

CI 保留 `main`、`master` 和 `workflow_call`，并检查向 `release/*` 的 push 及以其为目标的 PR；公开文档工作流覆盖相同分支范围。普通检查仅使用只读 token，不取得正式发布权限。维护者须在版本分支承接功能 PR 前核验真实检查名称、required checks 与分支保护，并验证必需检查失败会阻止合并；本地触发回归不能替代这项远端验收，见 [版本规范](VERSIONING.md#9-合并与发布门禁)。

hosted 发布验证由 [tests/release](../tests/release) 提供，使用专用临时环境和绑定构建 SHA 的证据。不得在生产数据库上试跑发布验证。PR 中注明执行的测试范围、结果以及尚未验证的部分。
