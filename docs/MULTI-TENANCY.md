# 核心多租户管理

✅ Plan Core 已完成（2026-09-23）：核心实现、自动化回归及本地浏览器验收完成；尚未提交或发布。

## 范围与部署

默认 `TENANT_MODE=single` 保留默认租户登录。多租户部署使用 `TENANT_MODE=hosted` 和
`TENANT_HOSTED_LOGIN_ENABLED=true`；全局关闭该开关后拒绝业务租户运行，默认租户仍可登录维护。
生产 hosted 仍须设置完整 `RELEASE_BUILD_SHA`。旧 `TENANT_HOSTED_CANARY_TENANT_ID` 仅保留兼容监控配置，不再限制可用租户数量。
登录使用租户代码或配置的 Host 后缀定位；未提供 locator 时使用 default。定位与凭据、数据库租户状态的验证不可互相替代。

## 管理流程与权限

默认租户启用的系统超级管理员角色通过普通登录会话进入租户管理。账号名称不授予权限。
管理调用 `/platform/tenants` 列表/创建、`/{tenant_id}` 摘要、`/bootstrap` 初始化、
`/activate` 启用或重新启用、`/disable` 停用。模型策略使用现有 `/ai/model-policies` 子资源。
创建和初始化分别携带稳定的 Idempotency-Key；失败时保留当前步骤，重试原请求。
初始化创建 admin、租户管理员/普通用户角色、必要菜单、默认模型策略和 Agent 绑定，密码只在请求内传输。
新租户同时初始化非公开配置 `ai:enabled_tools=["file.parse"]`，使文件解析权限与实际工具入口一致。
已有租户不自动覆盖配置；需要文件解析的既有部署应由维护人员按租户补齐缺失配置，保留已有显式禁用值。
未初始化不能启用。停用保留数据，重新启用不重置密码或角色；状态变化由数据库递增安全版本，旧 token 不能复活。

独立平台维护身份保留在 Provider/模型目录维护、支持日志和审计 retention 等运维 API。
普通租户管理不接受该身份代替系统角色。所有全局管理需 reason/ticket/correlation，授权意图独立留存，
成功审计与业务事务原子提交，用户操作记录真实 user ID、目标租户和结果，不伪造 platform principal。
每次请求重新读取当前角色和租户状态，撤权立即生效。

## 决策记录

1. **多业务租户共存** — 以部署开关和数据库合法启用状态共同控制访问。**反例**: 删除状态/版本验证以绕过灰度。**回归**: 核心 runtime、认证、worker 与生命周期测试。
2. **系统会话复用** — 扩展现有系统角色控制面，租户管理员只管理本租户。**反例**: 按 admin 名称提升权限或给普通管理增加第二次登录。**回归**: 系统角色 HTTP 拒绝与审计测试。
3. **重新启用保留撤销边界** — 复用状态版本触发器和初始化保护。**反例**: enable 后允许旧 access/refresh/worker authority 再次使用。**回归**: 生命周期版本及认证撤销测试。
4. **工具配置纳入原子初始化** — 新租户以固定安全默认值启用文件解析，初始化前检查配置残留，避免有权限却没有工具入口。**反例**: 复制默认租户的可变配置或覆盖既有租户显式禁用值。**回归**: `tests/modules/platform/test_tenant_bootstrap.py` 的初始化、回滚和并发幂等测试。

本期不开放 Marketplace/Lowcode、跨租户成员关系、在线租户切换、BYOK。

## 验证记录（2026-09-23）

- 后端全量 2853 项通过，覆盖率 79.71%；Ruff 检查与格式检查通过。
- 前端全量 69 个测试文件、286 项通过；语句/分支/函数/行覆盖率分别为 81.57% / 71.59% / 72.13% / 84.95%。类型检查、静态检查及生产构建通过。
- 本地 hosted 验收使用独立 API 端口 18080，三个前端 origin 同时保持 default、core-a0923、core-b0923 会话，原服务配置保持不变。
- 默认租户系统管理员完成创建、初始化、启用；两个业务租户使用同名 admin 各自登录，用户/角色、部门、AI 历史及文件列表隔离。业务租户直接访问租户管理返回无权限。
- 甲租户 CSV 附件成功解析专用标记和数值；乙租户看不到该附件。甲 AI 查询结果在甲可读，乙回放同一结果 ID 返回 404。
- 甲导出一行用户数据，浏览器点击下载触发后端 200。停用后旧确认请求、刷新令牌及旧下载请求返回 401；重新启用后旧下载仍返回 401。甲、乙重新登录成功，原数据保留。
- 临时撤销乙的默认模型策略后，旧聊天页面发送请求提示模型不可用；恢复允许使用、默认模型及不限额度后再次查询成功。

浏览器下载事件未被自动化工具捕获，因此上述下载验证确认到了响应成功与撤销拒绝，未宣称已核验用户下载目录中的文件。本次未在浏览器逐项重放跨租户直接下载 ID 和 worker authority；自动化回归另行覆盖认证版本、结果投影撤权及 worker 验证。

验收租户在修复前已经初始化，验收时仅补齐了它们缺失的文件解析默认配置；新租户自动种子的正确性由初始化、回滚及并发测试验证。该过程没有修改原部署配置或既有业务租户设置。

生产发布需另行执行针对目标构建的部署验收；旧 `qualify_tenant_hosted_release.py` 的单 canary/独立平台身份流程不能作为本次多租户系统会话管理的发布证明。
