# 安全说明

本文说明当前后端的安全边界，供部署者和贡献者使用。AI 特有行为见 [AI 安全](AI-SECURITY.md)。配置来源以 [app/core/config.py](../app/core/config.py) 和当前版本环境模板为准。

## 认证与授权

JWT Bearer 的密钥由部署配置提供，禁止把示例密钥用于生产。密码使用 bcrypt；初始管理员密码由 CLI 生成并保存在部署配置中，不进入初始化日志。令牌、密码和 Provider 凭据不应出现在日志、截图或 Issue。

功能权限由后端检查，前端按钮可见性只改善交互。超级管理员由启用的角色决定，账号名 `admin` 不授予特权。租户管理员只能操作所属租户；系统级操作与独立平台维护身份各有明确入口，不能相互替代。

每次请求使用认证产生的可信租户上下文。列表、详情、写入、关联、计数、缓存、文件和后台任务均需同一隔离边界。部门数据范围不能代替租户过滤，详见 [多租户](MULTI-TENANCY.md) 与 [数据权限](data-scope-guide.md)。

## 输入、文件与出站请求

- 使用 Pydantic 边界校验和参数化 SQL；动态标识符必须经过受控白名单。
- 文件同时检查场景允许类型、大小、内容、路径与归属。私有附件不挂载为公共静态目录，代理也不能绕过鉴权提供私有目录。
- 上传硬上限、租户偏好、解析器限制分别生效，见 [系统设置](SYSTEM-SETTINGS.md)。扩展名选项不表示每个上传场景都支持该格式。
- AI Provider 出站使用精确 origin 允许列表、DNS/IP 验证及连接约束；不能通过关闭校验解决连接失败。配置与诊断见 [AI 部署](AI-DEPLOYMENT.md)。
- HTTP 登录、注册和 API 限流依赖 Redis；超额返回 429，限流存储故障返回 503。不要将故障改成无条件放行。

## 审计与部署责任

HTTP 操作、AI 工具执行和平台操作有不同审计入口。敏感字段脱敏，平台成功审计与业务事务在 HTTP 成功响应发送前原子提交；提交或审计失败时不得返回成功。租户激活、禁用成功后，后续请求立即读取已提交的状态。数据库迁移中的审计限制和安全版本触发器必须保留，不能仅靠 ORM 自动生成结构替代。

生产部署使用 HTTPS、受限数据库/Redis 网络和安全的备份访问权限。保留日志应与部署方的数据治理要求一致；开源代码不替部署方提供备份、值班或托管服务承诺。

## 报告漏洞

不要在公开 Issue 上传利用步骤、令牌或个人数据。优先查看本仓库 GitHub Security 页的 **Report a vulnerability** 私密报告入口；若仓库尚未开启该功能，先通过维护者公开的联系渠道取得私密报告方式。也可创建不含漏洞细节的 Issue，仅请求私下联系。

私密报告应包含受影响版本、最小复现、影响范围和脱敏证据。修复及披露安排由维护者与报告者协商；本文不承诺尚未建立的响应时限、漏洞奖励或长期支持周期。使用已发布版本时关注对应 Release 的安全说明。
