# 安全说明

本文说明当前后端的安全边界，供部署者和贡献者使用。AI 特有行为见 [AI 安全](AI-SECURITY.md)。配置来源以 [app/core/config.py](../app/core/config.py) 和当前版本环境模板为准。

## 认证与授权

JWT Bearer 的密钥由部署配置提供，禁止把示例密钥用于生产。密码使用 bcrypt；初始管理员密码由 CLI 生成并保存在部署配置中，不进入初始化日志。令牌、密码和 Provider 凭据不应出现在日志、截图或 Issue。

功能权限由后端检查，前端按钮可见性只改善交互。超级管理员由启用的角色决定，账号名 `admin` 不授予特权。租户管理员只能操作所属租户；系统级操作与独立平台维护身份各有明确入口，不能相互替代。

每次请求使用认证产生的可信租户上下文。列表、详情、写入、关联、计数、缓存、文件和后台任务均需同一隔离边界。部门数据范围不能代替租户过滤，详见 [多租户](MULTI-TENANCY.md) 与 [数据权限](data-scope-guide.md)。

### 内部授权事务协议

后端提供显式选择的 [AuthorizationPlanSession](../app/db/authorization_plan_session.py) 和[事务计划执行器](../app/modules/system/service/authorization_transaction_service.py)。它们从会话首次 SQL 记录历史，在全局 guard、完整租户屏障及固定顺序的资源锁实际取得后生成当前事务内的证明。普通入口和原有会话工厂尚未接入此协议，字段策略尚未启用；这些内部原语不替代身份认证、租户校验或业务授权。

调用者须使用新建的专用会话、一次声明完整资源计划，并由事务所有者在成功退出后提交，失败后回滚。普通范围最多32个租户；全局范围在独占 guard 内自行枚举全部状态的租户，最多1024个，缺屏障或超量直接拒绝。资源目录固定，不接受调用者提供表名、锁 SQL 或“已经持锁”的声明。新行证明仅在预声明的受控 INSERT 成功后产生，SAVEPOINT 回滚撤销其新增证明；开户的结构事务不由此通用 INSERT 接口承接。

默认事务预算15秒，上限60秒；连接等待与整段 guard/屏障获取共用至多2秒，单条数据库语句至多5秒，均受剩余预算限制。提交仍由外层所有者负责。受保护范围允许可识别的 SQLAlchemy 纯读取；函数仅放行参数为字符串的 schema 限定 `pg_catalog.lower` 和 `pg_catalog.concat`，未知函数、原始文本、直接锁写、流式结果、原始驱动与同步回调出口均拒绝。连接接口只提供受观察的读取/执行方法，提交和回滚使用会话接口。此协议约束受信任应用代码的公开异步调用，不是执行不受信任 Python 的沙箱，也不允许通过底层同步会话、私有成员或额外连接绕过它。

专用会话的事务查询只返回只读状态，禁止通过 transaction 对象提交或回滚，也不支持裸 `begin`、`begin_nested`、`merge`、`delete`、`reset` 或 `invalidate`。SAVEPOINT 只能由计划句柄创建与结束，创建/释放失败使整个外层事务失效；所有者通过会话 `rollback` 或 `close` 清理。后续业务写适配必须显式纳入协议，不能借这些 ORM 入口补写。

内部候选组合入口覆盖 System 用户、角色、部门及关联写入、账户注册/恢复/绑定、导入执行和策略持久化，登记见[候选入口清单](../app/core/authorization_candidates.py)。这些入口尚未接到生产 HTTP/AI 工厂，不表示现有业务已启用完整屏障或字段策略。候选会先计划所有既存资源和新行键，再通过固定键受控 DML 写入；不接受普通会话，也不按证明是否存在回落到旧写者。

候选范围还包括菜单与按钮、角色 Agent 关联、Agent/Provider/Model 目录、租户模型策略、设置、邮件配置、租户开户与引导、独立平台身份和日志 retention。全局授权事实实际变更在独占 guard 和全部租户屏障内推进全局及全部租户 epoch；仅涉及目标租户的操作只推进目标 epoch。登录时间、邮件测试状态和审计追加不推进授权 epoch。结构开户通过专用入口插入 Tenant 并立即锁住触发器建立的新屏障，推进全局 epoch，既有租户 epoch 保持不变；幂等重放不推进。

Provider DNS 校验、模型探测、邮件发送和配置文件解析分离到无数据库事务阶段，分别采用2秒、15秒、15秒和3秒预算；模型探测不自动重试，输出最多16个 token。配置导入限制10MiB文件、1000行、单值8KiB和累计1MiB值。探测准备结果只能使用一次，完成时重新取得证明并检查当前配置及身份；外部结果不能覆盖已更新配置。确认提交后的缓存清理最多256键/1秒，超量明确返回延迟刷新状态，旧缓存最多保留既定300秒。

平台写入先独立提交必需授权意图，成功完成审计与业务同事务；业务失败回滚后独立追加失败完成。System 用户和 PlatformPrincipal 使用不同审计来源，不能互相伪装。首次建立 PlatformPrincipal 时因尚无合法主体外键，主体与两条审计在同一事务创建。平台权限离线替换及种子候选须提供受信任部署观察器签发的30秒停写凭据，证明 API、worker、scheduler 和旧 Web 写入口均停止、在途写者为零，且构建与维护清单匹配；库不默认提供生产观察器。离线种子的维护清单回执由调用方保管，不冒充已存在主体的数据库审计。此凭据和候选代码不代表部署现场已经停写；旧脚本及生产入口尚未切换。

授权对象的真实写入由聚合账本驱动，同一聚合成功后将租户 epoch 推进一次并使 ready 候选回到 legacy，保留候选摘要和历史。SAVEPOINT 回滚撤回该范围的新增证明和变更记录；无实际变更、重放或全失败导入不推进 epoch。候选角色删除在任何子删除前检查整批策略历史，存在活动或归档历史均返回 `ROLE_DELETE_POLICY_HISTORY_REFERENCED`，不通过删除历史解除引用。

候选 System/导入读取按累计10万行、64MiB解码预算拒绝超限；显式普通数组最多256项，导入最多2000行、10MiB输入及10MiB错误产物。策略来源两阶段合计同样最多10万行/64MiB，历史规则 manifest 另有既定128MiB预算。这些是逻辑读取限额，不是进程内存硬上限。本地同步文件操作继续使用原有归属协议，协作式 deadline 不保证中断操作系统磁盘调用；原始上传文件的归属核验和 AI 完成事实仍须由实际 owner 提供。

密码计算和外部一次性证明位于屏障之外，消费证明后仍重验当前数据库身份与授权。辅助缓存仅在确认提交后执行。候选 owner 只允许健康且已结束的保护范围进入独立8秒提交 ACK 阶段；结果未知则隔离会话和在途操作，等待连接失效处理，禁止自动重执业务或据此删除未知归属的产物。普通 Service 不提交外层事务。

## 输入、文件与出站请求

- 使用 Pydantic 边界校验和参数化 SQL；动态标识符必须经过受控白名单。
- 文件同时检查场景允许类型、大小、内容、路径与归属。私有附件不挂载为公共静态目录，代理也不能绕过鉴权提供私有目录。
- 上传硬上限、租户偏好、解析器限制分别生效，见 [系统设置](SYSTEM-SETTINGS.md)。扩展名选项不表示每个上传场景都支持该格式。
- AI Provider 出站使用精确 origin 允许列表、DNS/IP 验证及连接约束；不能通过关闭校验解决连接失败。配置与诊断见 [AI 部署](AI-DEPLOYMENT.md)。
- HTTP 登录、注册和 API 限流依赖 Redis；超额返回 429，限流存储故障返回 503。不要将故障改成无条件放行。

## 审计与部署责任

HTTP 操作、AI 工具执行和平台操作有不同审计入口。敏感字段脱敏，平台成功审计与业务事务在 HTTP 成功响应发送前原子提交；提交或审计失败时不得返回成功。租户激活、禁用成功后，后续请求立即读取已提交的状态。数据库迁移中的审计限制和安全版本触发器必须保留，不能仅靠 ORM 自动生成结构替代。

生产部署使用 HTTPS、受限数据库/Redis 网络和安全的备份访问权限。保留日志应与部署方的数据治理要求一致；开源代码不替部署方提供备份、值班或托管服务承诺。

## 报告漏洞

不要在公开 Issue 上传利用步骤、令牌或个人数据。优先查看本仓库 GitHub Security 页的 **Report a vulnerability** 私密报告入口；若仓库尚未开启该功能，先通过维护者公开的联系渠道取得私密报告方式。也可创建不含漏洞细节的 Issue，仅请求私下联系。

私密报告应包含受影响版本、最小复现、影响范围和脱敏证据。修复及披露安排由维护者与报告者协商；本文不承诺尚未建立的响应时限、漏洞奖励或长期支持周期。使用已发布版本时关注对应 Release 的安全说明。
