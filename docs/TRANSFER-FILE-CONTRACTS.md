# 传输与文件字段契约

Backend/Web 0.2.0 开发版本的准备目录包含23个对象；其中历史十四对象包括十个基础对象及 `system.file`、`transfer.import`、`transfer.export`、`transfer.audit`。历史目录和摘要独立保留，新增 AI 与审计对象见 [AI 交付字段契约](AI-DELIVERY-FIELDS.md)。该目录与运行适配器不代表生产激活资格；完整交付、恢复和独立复核仍是发布前置条件。

## 授权与来源

功能权限、租户、记录范围和字段用途必须同时满足。读取不授予查询、导入匹配、导入创建/更新/关系替换或导出。导出的每个用户字段同时要求当前读取与导出许可；电话号码、邮箱仍受掩码上限约束。通用策略路径只查询授权 SQL 投影，不加载完整目标用户实体。全部拒绝的列省略，混合记录中拒绝的单元格显示“未授权”。

查询用途在施加客户端筛选、分页或计数前，对完整的服务端基准范围证明。`filter`、`join`、`match` 分开判断。导入解析器实际在租户完整候选域匹配用户名、员工号、启用部门和角色，因此调用者需要覆盖这些候选域的导入精确匹配许可。新目录给部门名、角色名/编码增加独立匹配用途；历史策略迁入只复制旧规则，不自动授予新用途。

导出的部门路径依赖各级部门名和父关系；多部门按部门 ID 升序选择第一项，最多 65 级。角色编码依赖角色编码与状态。来源中任一字段不可读、记录不可见或关系损坏时，整个派生单元格隐藏。模板字典仅在实际来源域完整可读时提供；否则省略整个字典，不用 ID 补位。固定表头和演示值不授予导入能力。

文件谱系只记录租户、所有者、资源、摘要、授权版本、结构记录标识和字段来源，不保存授权令牌或源业务值。每次重新下载均验证当前身份、功能、用途、来源、G/B epoch 和文件摘要；证明失效要求重新生成。谱系不是授权凭据。

内存中的单份通用来源证明最多 4 MiB、16384 项来源；落库前，包含预检源和错误证明的整个谱系包仍受原 JSONB 文本 2 MiB 上限约束，按包含空格的 UTF-8 字节核验，超限整体拒绝并回滚。较大的来源集合需要缩小导出范围，不能通过扩大表约束绕过既有预算。

## 接口与稀疏元数据

传输任务 ID 是逐字保留的不透明 URL-safe 字符串，字段契约允许1–64个 ASCII 字母、数字、`-`、`_`，首字符可以为 `-` 或 `_`。不重新生成或改写已有 ID，不将其当作数字、文件路径或 SQL 标识符。Snowflake ID 继续使用正十进制整数字符串；租户、所有者、功能权限与字段用途校验保持有效。

用户传输沿用 `/system/user/import`、`/import/template`、`/import/{batch_id}`、`/import/{batch_id}/logs`、`/import/{batch_id}/cancel`、`/export`、`/export/{export_id}`、`/export/{export_id}/download`；错误文件通过 `/system/file/import-error/{batch_id}.xlsx` 认证下载。预检回执包含 `batchId`、`previewToken` 和过期时间；预检不是正式写入授权。执行前重新校验输入、模式和完整写入足迹。

通用策略下，任务列表、详情和审计返回闭集稀疏 DTO 及 `fieldPolicy.read/query/canDownload/canCancel`。未授权属性不出现，不补默认零值；合法零值仍保留。操作人名称继承用户名称来源授权。原始文件名使用固定安全显示名，原因、筛选快照、自由错误文本、内部操作人 ID、磁盘路径和存储 key 不进入这些 DTO。没有通用策略 head 的历史摘要保留明确的旧兼容协议。

文件列表、详情使用 `fieldPolicy` 控制字段与搜索；认证 `GET /system/file/{file_id}/download` 交付内容。`system:file:list` 是列表、详情及下载的功能前提，上传仍需 `system:file:upload`。普通角色仅访问自己在本租户的文件，超管可在本租户管理文件，均不绕过字段拒绝。上传回执为固定资源标识和公开图片地址（私有文件地址为空），可读元数据按当前策略省略。

AI 聊天图片为兼容现有消息协议仍返回稳定引用地址；该地址无法匿名读取，客户端必须经过 `/system/file/chat-image` 认证接口取得当前授权的图片。引用不授予内容读取能力。

Web 沿用现有角色字段配置、文件页和用户传输弹窗。文件页通过认证 API 下载，不复制原始存储地址。历史列、详情和查询控件按服务端能力显示；能力提示不替代服务端复核。导入预览绑定文件、原因和冲突策略；修改后需重新预检。模式在确认时选择并重新证明。重复点击受在途屏障限制，关闭或重开弹窗后旧响应不能下载或覆盖状态。当前用户导出接口支持账号、昵称、邮箱、手机号、状态、精确账号名单及部门筛选；Web 遇到性别或角色筛选时明确阻止导出，不能静默扩大结果集。

## 文件分类与 IO 边界

普通上传默认私有。只有显式 `avatar`、`brand` 的已验证 JPEG/PNG 使用固定公开图片协议。AI 图片和文档、用户导入源文件均私有。客户端 `business_id` 不能创建可信业务来源关联，当前上传入口在读文件前拒绝该参数。已知扩展名、场景大小、声明 MIME 与内容格式共同校验；容器签名识别格式族，不能替代业务解析器的安全检查。批次在任何文件落盘前完成整批内容校验。

新增文件保存 `delivery_class`、SHA256 和闭集来源登记。历史文件保持 `legacy-unknown`，不猜测所有者之外的业务来源；匿名静态兼容仅允许确实被当前头像或品牌设置引用的历史 JPEG/PNG。未知附件不能直接公开，须重新上传或另行受控迁入。GET、HEAD、条件请求均先分类。下载附带 attachment、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff` 和禁止引用来源的响应头。

普通文件下载在独立事务内准备快照，关闭事务后用有界 worker 读盘，再用新事务复核；撤权后不交付字节。普通上传与模板编码也在数据库事务外。既有持久传输资源的本地发布/读取保留事务所有者的有界 `file_io` 原子协议，不能替换为网络存储或无界 IO。文件下载上限为普通文件 100 MiB、图片 20 MiB；worker 时间预算 3 秒。上传批次最多 32 项、总计 100 MiB，用户同步导出最多 5000 行。

## 迁移与恢复

当前 Alembic head 为 `e020f3a00001`。迁移保留旧文件元数据和路径，以 `legacy-unknown` 为默认分类；数据库约束拒绝不完整或未知的新来源证明。受控安装接受本系列已知前置 head，未知或分叉 head 拒绝，不能通过 `stamp` 跳过迁移。

存在新来源文件或通用策略曾经 enforcing 时，降级拒绝丢弃来源列。恢复必须使用一致的数据库与文件备份，并匹配 Backend/Web、迁移和目录版本；不能只降级数据库或只回退 Web。直接启动合并模式、API/独立 scheduler 模式及现有 Docker Compose 均沿用[维护证据协议](AUTHORIZATION-MAINTENANCE.md)，完整停写和在途核验不能由 Ctrl+C 代替。
