# 授权维护的停写与恢复

本手册面向后端维护者，说明直接启动和 Docker Compose 的停写控制。应用仍支持开发环境的 API 与 scheduler 合并运行，以及 API、独立 scheduler 分开运行；AI 启动恢复和过期扫描属于 API 进程。维护工具不要求增加部署平台。

应用通过 `AUTHORIZATION_CONTROL_DIR` 指定持久控制目录，默认 `.local/runtime/authorization`。同一部署的所有 API、scheduler 和维护控制器必须看到同一目录。Compose 应把同一个宿主机目录挂载到这些容器，并配置对应容器内路径。目录仅向部署管理员和应用运行账号开放写权限，不能作为公开上传目录或静态资源目录。

## 停写边界

`stop.json` 存在或控制文件无法读取时，服务端拒绝新 HTTP 请求，返回 HTTP 503、业务码 503、`errorCode=AUTHORIZATION_MAINTENANCE_ACTIVE`；WebSocket 使用关闭码 1013。GET 也被阻断，因为部分读取入口会执行恢复或日志写入。检查发生在认证和业务数据库访问前，不信任客户端版本头，旧 Web 直接发送请求也受限制。

后台调度、AI 恢复与扫描入口同时关闭接纳。已经进入的请求可以完成；新任务不能继承父任务的接纳资格。进程一旦进入停写状态，即使删除控制文件也不会自行重新开放。正常关闭会等待已启动的后台资源清理；Ctrl+C、信号处理器返回、活动任务数或 `quiesced` 记录均不能单独证明停写。

维护控制器还必须核对以下事实：

- 直接启动：清单中的每一个 PID 与内核创建代际匹配，所有登记的存活进程都在清单中；实际进程已经退出。Windows 虚拟环境启动器、reload 进程和 supervisor 可能拥有独立 PID，也必须纳入清单。PID 复用或不可观察状态会被拒绝。
- Compose：精确 project、service 与完整容器 ID 对应，相关服务没有额外实例；重启策略已设为 `no`，容器不处于运行、重启、暂停或异常 dead 状态。原重启策略保存于控制记录。停止命令成功不能替代再次检查。
- PostgreSQL：目标数据库已设置 `ALLOW_CONNECTIONS=false`，没有应用会话、在途事务或 prepared transaction。包括空闲应用池连接在内的任何额外会话都会阻断证明。

数据库开关会阻止包括超级用户在内的新连接；`CONNECTION LIMIT 0` 不具有相同保证。控制连接使用同一服务器上的 `postgres` 数据库（目标为 `postgres` 时使用 `template1`）。关闭前预热两个维护池连接，逐一记录 PID 与 backend_start；观察时它们必须全部空闲且无事务。维护动作随后从这个池创建新的严格会话。[PostgreSQL 数据库连接开关](https://www.postgresql.org/docs/16/sql-alterdatabase.html)

当前控制器要求数据库管理员权限，并拒绝启用逻辑复制订阅或未知 `shared_preload_libraries` 的目标；允许空配置和 `pg_stat_statements`。这些额外数据库写者需要独立适配，不能通过忽略检查放行。

## 清单与命令

先检查帮助：

```bash
python -m tools.ops.authorization_maintenance --help
```

清单是最多 64 KiB 的运维 JSON，包含且仅包含 `manifest`、`application_roles`、`processes`。`manifest` 包含 `deployment_id`、40 位小写十六进制 `build_sha`、`mode`（`direct` 或 `compose`）和 `surfaces: ["api", "scheduler"]`。合并运行仍覆盖这两个 surface。`build_sha` 必须与控制器的 `RELEASE_BUILD_SHA` 相同。

直接启动的 `processes` 为 `{"mode":"direct","identities":[{"pid":12345,"birth":"..."}]}`。`birth` 必须是实际内核代际：应用登记文件中的 `identity` 可用于收集运行实例；启动器和 supervisor 使用 `app.core.process_identity.ProcessIdentity.read(pid)` 读取。不能用 PID 数字、进程名称或手工时间戳替代。控制目录的进程记录不能删掉以规避清单完整性检查。

Compose 的 `processes` 为 `{"mode":"compose","project":"deployment","services":{"api":["完整容器ID"],"scheduler":["完整容器ID"]}}`；只选择应用服务，不选择 PostgreSQL 或 Redis。每个服务都要列出全部实例；合并模式只列实际承载两种职责的服务。

`application_roles` 列出该目标库的应用数据库角色。数据库连接信息只通过 `AUTHORIZATION_MAINTENANCE_DATABASE_URL` 环境变量传给控制器，不能放入清单或命令参数。工具不输出连接串或密码。

```bash
python -m tools.ops.authorization_maintenance stop --inventory deployment.json --control-dir CONTROL_DIRECTORY
python -m tools.ops.authorization_maintenance observe --inventory deployment.json --control-dir CONTROL_DIRECTORY
python -m tools.ops.authorization_maintenance execute --inventory deployment.json --control-dir CONTROL_DIRECTORY --action seed.settings
python -m tools.ops.authorization_maintenance resume --inventory deployment.json --control-dir CONTROL_DIRECTORY
```

`stop` 和 `execute` 都从尚未关闭的部署开始，独占创建控制记录；不能在 `stop` 之后再运行 `execute`。需要维护动作时直接使用 `execute`，它在一次控制会话内完成关闭、停止、独立观察、固定 owner 执行和最终空闲核验。控制器退出后不会自动开放数据库或入口。

当前固定动作是 `seed.system`、`seed.agents`、`seed.settings`、`principal.create` 和 `principal.permissions`；不接收任意 SQL、脚本、回调或 session factory。种子管理员密码或平台主体密码由 `AUTHORIZATION_MAINTENANCE_PASSWORD` 传入。平台主体动作另需 `--payload` JSON，包含 `principal_name`、`permissions`、`reason`、`ticket_id`、`correlation_id`，创建时另含 `display_name`。密码不能放入 payload。既有业务校验、权限清单、审计和唯一事务完成规则仍然生效。

## 失败与显式恢复

失败、取消、控制器崩溃或观察不确定时保留停写状态。新的控制器可以通过控制数据库执行 `observe` 或 `resume`；不能在目标库仍关闭时重新创建维护池并重放未知动作。业务提交返回 `AUTHORIZATION_COMMIT_UNKNOWN` 时保持未知，不按普通失败重试。

`resume` 重新核对清单、实际进程停止及数据库空闲；最近签发的 30 秒证明尚有效时拒绝恢复。成功后恢复原数据库连接开关并移除停止标记，不启动应用，也不恢复 Docker 重启策略。部署管理员应先确认维护结果和待启动构建，再按记录恢复所需重启策略并启动已核对的实例。原进程不能靠删除文件重新进入。

当前维护入口和停写机制已经接入实际启动路径；完整业务授权 owner 的生产迁移仍有未接入入口。这些控制能力不能作为全业务授权屏障已经开放、字段策略已启用或版本已经发布的证明。

## 用户导入与导出

REST 用户导入预检、正式导入、取消、导出和管理端重下载已使用固定事务 owner。旧 Web 请求无需额外提供锁、epoch 或来源证明；这些信息由服务端从当前身份及数据库事实生成并核验。上传读取和表格解析先释放请求数据库事务，随后在授权保护区内重新检查文件策略和完整资源计划。

表格解析和生成受 3 秒、2 个工作线程及 8 个排队任务的限制，处理线程只接收字节或已投影的字段值。导出最多 5000 行、文件最多 10 MiB；超过限制会拒绝本次请求。超时后不会继续发布文件。已完成导出的首次响应使用提交前冻结的文件内容和文件名，未知提交结果不会自动重试。

管理端重下载沿用本人或当前超级管理员的权限检查；AI 签名下载另有来源授权契约。旧无 manifest 文件只允许核验数据库归属后的只读下载。取消预检先提交取消状态，再由新的授权事务核验并退役文件；未知提交结果保留文件。运行中导入的取消响应不构成业务已回滚的证明。

AI 签名下载也使用独立授权事务：锁内重验签名的用户、租户、资源、来源及当前 Agent、工具和数据范围权限。签名最长 16 KiB；签名或投影拒绝保持 404。即使当前用户是超级管理员，也不能凭 AI 签名跨操作人下载。

原有三个定时清理任务每次推进最多 256 个引用，并保存独立游标。预检有效期为 10 分钟，终态导入保留 90 天，终态导出保留 30 天；CREATED、RUNNING 和未知完成不能仅凭年龄清理。事实到期提交确认后，再以新事务核验文件归属并退役。预检到期仍追加 EXPIRED 日志。历史资源行保留以供完成核验，任务计数表示当页已确认退役的资源数，不表示删除的数据库行数。

## HTTP 授权写事务

用户基本信息、个人资料、密码、会话撤销、角色和部门分配、用户删除，以及角色和部门的管理写入，使用独立的授权事务 owner。注册、密码找回、邮箱绑定和验证码准备、登录及刷新也使用固定 owner。认证读取完成后释放原请求事务，后续请求会话不能再次执行 SQL 或提交；业务 owner 是唯一业务提交者。

写入重新核对已验证 JWT 中的用户和租户安全版本、当前权限及完整锁计划。请求开始后的撤权不会被旧 ORM 对象或客户端版本声明绕过。用户删除同时检查并锁定 AI 历史依赖；未决、未知或尚未清理的文件引用保持拒绝，不自动重试删除。

登录审计保持独立追加事务，密码哈希、验证码及通知工作使用既有累计预算。`AUTHORIZATION_COMMIT_UNKNOWN` 表示未得到确定的提交结果，不能按普通业务失败自动重放。上述入口接入不表示其余业务写者已经全部迁移，也不启用字段策略。

菜单、配置导入与管理、设置、邮件测试和角色 Agent 绑定也使用固定 owner。全局 Agent、Provider、Model 和租户模型策略写入保留原有审计头要求；模型探测先释放准备事务，再执行有时限的外部请求，返回后重新核对身份与配置。验证失败会追加一次失败完成，未知提交结果不会追加相反的完成记录。

租户准备、引导、激活和禁用在计划事务中执行。首次准备的审计意图尚无目标租户，目标 ID 在全局排他锁内按幂等键分配或复用，并写入完成摘要；同键、同内容的并发请求返回同一租户。不同内容继续返回幂等冲突。

独立平台 Principal 的登录和身份查询使用全局授权 guard。Support 审计查询及 retention 使用冻结的 Principal 安全版本、固定路由和目标租户，分别完成身份读取、审计意图和业务事务。Support 只返回既有脱敏投影；retention 仍只处理明确归属租户的日志，并核对保留窗口与预期数量。

## API 后台恢复

会话创建、修改和删除通过固定 owner 完成。模型选择及 DNS 检查先释放数据库事务，再在完整计划内重验当前身份与模型配置。创建响应在提交前冻结；未知提交结果不会自动重建会话。删除在同一事务终结待确认动作并软删会话；未决执行或损坏完成返回 `AI_ACTION_RUNNING`，已验证只读历史仍可删除。

AI 启动恢复和过期扫描继续运行在 API 进程中，并受同一个持久停写屏障约束。数据库扫描每页最多 256 个引用，每条通过独立的授权事务核验完整聊天、动作和日志关系。页面保留游标；30 秒后不再开始下一条，已经开始的事实核验、缓存和展示工作仍分别受 8 秒、2 秒和 8 秒预算约束。维护期间不能重新进入扫描。

未到期且来源有效的待确认动作不会因 Redis 丢失而过期。启动前的只读批准动作、过期的执行租约和失效来源分别按数据库事实处理；数据库及文件工具的未决完成仍需要正面证明，恢复流程不会重新调用工具执行器。提交结果不明时保留缓存和文件，不追加失败展示，也不重放业务。

缓存清理只在确认数据库事实后执行。遗留 Redis 缓存每次最多处理 64 项，单条读取最多 64 KiB；没有完整日志绑定、工具分类不符或关系损坏时保留未知状态。后台展示使用当前用户权限和单独的完整锁计划；撤权后可跳过展示，但不会改变已经确认的业务事实。旧只读工具的文本摘要不能用来重建成功结果。


平台 Agent、Provider、Model、租户模型策略和租户目录 GET 同样使用固定审计 owner。需要 DNS 的目录查询先释放数据库事务，再进行最多 512 项、10 并发、总计 5 秒的网络检查；随后重验当前身份及配置快照。读取阶段各有 8 秒预算，授权意图与完成审计各只提交一次；提交结果未知不追加相反记录。

会话列表、详情和 Trace 查询使用独立的当前身份计划。会话详情、消息和待确认卡片在同一上下文锁内投影；请求开始后已撤销的身份不能继续取得正文。只读响应冻结成 DTO 后结束事务，不追加业务提交。


单条 AI 操作日志轮询也使用当前身份和完整上下文计划。完成分类与可见性来自同一数据库快照；缺少必需日志时只返回未知状态，不返回持久结果正文。已认领的 DB/FILE 执行由固定适配器完成业务、epoch、动作及日志提交；原请求必须已结束认领事务，未知提交不会降级到旧工具 handler 或自动重放。

## 通用文件上传与删除

确认提案通过固定事务入口保存。直接确认的 ID 在起始日志中分配，预览交接的执行日志使用服务端生成的同一确认 ID；创建动作时不再修改日志身份。当前身份版本、模型、Agent、工具权限、数据范围、消息依赖及原调用绑定均在完整计划内复验。Redis 提示创建与持久动作绑定各最多 2 秒，均在数据库事务外；数据库工作预算 8 秒，提交确认预算 8 秒。

预检将选择条件解析成确定执行参数时，起始日志与确认动作使用同一份冻结参数摘要。DB/FILE 确认等待超时以数据库时间核验是否到期，尚未到期或已被认领时返回待核对状态。确实到期的未认领动作与日志在固定事务中一致更新；提交未知不发布已过期结论。批准后的结果按原动作绑定和当前权限重新投影，无法读取的详情不会从旧缓存或旧数据库会话返回。

导入预览的确认交接还会核验原预览记录、批次和提案摘要。动作与日志更新后，在最后文件阶段复验源文件；每次读取最多 10 MiB、总计最多 20 MiB、最多两次读取。文件失败回滚交接事务。提交应答未知只能按原确认身份读取已保存事实，不能重新创建动作；回查同样核验当前权限及完整绑定。

单文件与批量上传先核验当前权限和策略，释放数据库事务后读取文件、验证图片并写入服务端生成的路径，随后在新完整计划内重验身份和策略并保存元数据。每批最多 32 个文件、合计最多 100 MiB，单文件仍受原场景策略的更小上限限制；请求读取预算 5 秒，磁盘及图片处理使用 3 秒有界 worker。线程只接收不可变输入，不持有数据库会话。超时的线程仍占用 worker 容量直至实际结束；未取得元数据提交确认的文件不会被自动删除或重试发布。

删除按当前所有者、超级管理员或批量删除权限核验，整批数据库删除成功后才回收磁盘文件。任一目标不存在或不可见使整批拒绝；未知提交 ACK 保留磁盘。已确认元数据删除后的磁盘超时会写入日志并保留不可访问的残留，需运维核对后清理。公开文件仍须经过服务端数据库分类检查，单独存在于磁盘不代表可访问。


确认入口的业务终态核对与会话展示分别完成。核对成功、失败以及从未执行的拒绝/过期记录时，均先取得全局授权保护及对应租户屏障，再验证完整上下文。已确认的业务成功不会因为可选展示更新超时或并发删除而改成未知；展示只按当前权限重新生成。没有已知提交结果的重复查询，仍须通过事实核验才能显示终态，不能重放业务。


DB/FILE 持久确认的批准、拒绝与过期检查使用验证后的 JWT 身份进入固定事务入口。拒绝不要求仍具有 AI 执行权限，但必须满足当前有效身份、原租户和原操作所有者。认领前业务重验失败，仅在已知回滚后，以新事务核验未曾执行并保存过期审计；并发已认领或损坏的证明保留为核对中。认领 ACK 未知不进入执行；拒绝 ACK 未知不发布已拒绝通知。输入准备最多 5 秒，独立认领事务预算 15 秒、提交确认预算 8 秒。Redis 禁用检查和提交后辅助记账各最多 2 秒，均在数据库事务外；辅助失败不改变已保存业务结果。

流式回复收尾在独立事务中重新核验原请求身份版本、消息来源及投影依赖。工具卡片根据已验证的数据库事实生成；模型输出不能证明写入成功。未知提交返回持久化失败，不自动重执行业务。恢复流的核对通知也通过同一固定入口保存，展示预算为 1 秒；会话清理超时不会覆盖已确认结果。

持久操作续传在等待通知前释放请求数据库事务。等待超时仅能将尚未认领的操作及日志一致记录为过期，来源绑定变化、旧身份、已认领操作或未知提交均保留为核对中。DB/FILE 终态回放在同一授权快照内验证完整完成事实、当前可见性和下载链接，读取不提交业务事务；拒绝或过期的最小状态也必须通过从未执行的事实证明。

聊天来源消息与成功路由审计在同一固定事务保存；失败或澄清只保存审计。来源写入前重验请求原身份版本、模型与 Agent 配置、工具开关、权限范围和历史消息依赖，同一会话的 trace 不允许重复使用。提交结果未知时不启动回复流。路由审计只保存输入 HMAC；消息继续执行敏感信息脱敏。只读准备阶段不再隐式修改会话的粘滞 Agent，新的会话模型、Agent 和 trace 随来源消息一并更新。

聊天模型选择在固定只读事务内冻结配置，结束事务后再执行 DNS 检查，最多 512 个候选、10 并发、总计 5 秒。来源写入仍绑定检查过的配置快照。Redis 安全检查、配额读写和会话租约准备各最多 2 秒，Supervisor 路由最多 15 秒，均在读取事务结束后进行；准备超时返回 `AI_PREPARATION_TIMEOUT`。

聊天本地图片和 `/system/file/chat-image` 均核验原请求身份、租户与文件所有者。文件元数据的准备和复验各为独立只读事务，文件读取和图片解码在 3 秒有界 worker 内执行；IO 期间元数据或身份变化时不返回图片字节。聊天每轮最多转换 32 个不同本地图片、合计 100 MiB，转换总预算 15 秒；已有更小单图片限制继续生效。图片响应保留 `no-store`，不依赖客户端版本或写保护标记。


Gateway 起始审计先核验原 JWT 身份及会话来源，以固定锁计划保存后才允许继续。审计提交结果未知时停止该次工具调用，不重试插入。兜底日志收尾同样单次提交，保留已经绑定持久动作、已有终态或核对标注的记录；业务写入成功只能由其原子执行 owner 保存。只读内置工具在当前身份、Agent、权限范围和来源依赖的同一计划内读取，结束数据库事务后才执行辅助 Redis 清理；辅助缓存失败不改变已取得的只读结果。

工具 dry-run 通过固定只读适配器重新核验身份、Agent、当前权限范围和消息来源，最多 8 秒且不提交事务。预检结果仅用于风险分类与确认展示，后续认领和执行仍需重新授权。部门查找最多读取 8192 个完整匹配项，超限拒绝；显示条数限制不截断用于投影授权的贡献记录集合。

## 导入预览的文件准备

导入预览先在固定只读授权事务中取得文件元数据与上传策略，再退出事务读取和解析文件。后台文件工作使用 2 个线程、8 个排队槽位和 3 秒等待预算；只接收不可变元数据或字节，不接收数据库会话。读取后重新核验原始身份、文件所有者、路径与上传策略，发布前再次验证元数据和策略。最终 FILE 阶段保留受事务预算约束的源文件摘要校验。

Gateway 的导入预览使用固定发布入口，复用已提交的原审计日志。文件工作开始前以及发布时均检查原身份、模型与提供商、消息来源、工具权限和数据范围。批次、文件归属与审计成功事实由同一完整计划保存；提交结果未知时只读核验历史事实，不重做预览。已完成调用再次进入时不再读取或解析文件，回放仅返回当前权限允许的最小回执，不返回可执行提案或确认令牌。


强制人工确认的内置只读工具也使用固定事务：在当前身份、模型、Agent、原消息和权限范围核验后，原子保存查询结果、字段来源及确认日志。数据库工作与提交确认各最多8秒；事务内不进行Redis或外部IO，授权epoch不因查询而变化。新结果包含绑定原动作及完整结果来源的内部摘要；历史成功文本不能替代该证明。重复确认只读取已经保存的结果，结果回放与背景展示均重新核验当前可见性。

持久确认的续传轮询只在短事务内读取原动作绑定的状态；返回连接后才等待下一轮。取消时回滚和关闭各保留0.25秒清理预算，清理不成功则隔离连接；这不会延长业务执行或提交确认的预算。

配额、连续失败和IP拒绝计数先通过固定只读事务读取内部白名单配置。配置阶段最多1秒、每字段最多2KiB，不提供业务授权；随后Redis步骤最多2秒。容量保护超时拒绝继续，提交后的辅助计数或清理失败不会覆盖已经确认的业务结果。IP黑名单计数不会在数据库事务中等待Redis。
