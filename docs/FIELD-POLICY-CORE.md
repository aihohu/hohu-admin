# 通用字段授权内部契约

本文面向后端维护者，说明 [field_policy](../app/core/field_policy/__init__.py) 的当前内部接口。纯内核负责目录、授权求值、查询表达式和来源证据；其持久化与候选管理见[通用字段策略存储](FIELD-POLICY-STORAGE.md)，全系统业务入口仍需接入。未迁入通用准备状态的用户入口继续遵循[用户字段契约](USER-FIELD-PROJECTION.md)。

## 调用前提与边界

目录和动作由服务器代码构造。`RecordContext` 必须来自已认证的事务所有者，包括可信租户、当前功能权限以及**对这一条记录适用**的角色集合。外部请求不能指定该集合、动作用途或授权规则。平台、系统和公共对象可以描述字段与来源，但不能编译成租户角色授予；租户 `0` 仍是租户域。

这些 Python 值和 `SourceRef` 都不是签名票据、数据库锁证明或认证凭据。内核不完成跨对象记录关联核验、当前身份刷新、epoch 核对、活动 manifest 加载或下载时复验。所有者仍需使用[授权事务协议](SECURITY.md#内部授权事务协议)，在保护期内完成这些检查。

## 目录和授权求值

- `Catalog` 接受不可变的 `ObjectSpec`、`FieldSpec` 和 `ActionSpec`。字段标识、别名、动作和依赖必须闭合且不重复；静态来源依赖不得循环。规范化摘要与声明顺序无关。
- `ActionSpec` 明确功能权限码和字段用途。数据动作必须有字段 footprint；特殊动作可以只声明对象和功能权限；导航动作不得携带数据访问。未知自定义按钮不会自动取得动作或字段许可。
- `Access(operation, purpose, use)` 区分读取、导出、创建、更新、关系替换以及查询用途。`management.query` 的筛选、关联、排序、分组、去重和聚合分别声明；导入匹配仅允许 `exact/import/match`。读取不会隐式产生查询权限。
- `compile_rules` 校验整个规则集合并建立只读索引。`resolve_fields` 检查动作功能码和字段 footprint；未授予即拒绝，适用角色中的显式拒绝优先。允许规则取最高读取等级，再受字段和动作上限约束。导出还需同记录的管理读取许可。
- 结构 ID 是已授权记录的定位字段，仅支持读取或导出，不可配置为通用写入口。其他字段没有默认允许。被拒绝字段的决策为 `hidden`。

`validate_write` 按实际提交字段检查权限，支持目录中显式声明的别名并拒绝重复归一字段。调用者必须在 Schema 默认值填充前保留字段存在性；值相等或提交 `null` 均不能绕过授权。它只检查权限，不代替业务值验证。

`project` 接受已规范化、字段闭集的普通映射，返回只读映射及冻结的嵌套容器。拒绝字段不下发；可空字段的 `null` 保持为空；ID 输出十进制字符串。只接受明确的值类型，拒绝 ORM、任意序列化对象、非有限数字和 JSON 内的日期对象。日期/时间字段保持原生值，HTTP DTO 负责既有时间格式。电话和邮箱使用固定掩码，不执行租户提供的表达式。

## 关系对象候选目录

`relation_catalog()` 提供包含用户、字典类型、字典项、数据范围演示、角色、部门和菜单的七对象目录，`production_catalog()` 当前返回该目录。七对象已接入受控准备流程，目录声明不能用于证明已取得生产激活资格。十对象纯候选及其未接线边界见[配置与任务字段候选契约](CONTROL-FIELD-CONTRACTS.md)。

角色定义、角色菜单、部门移动/成员和菜单注册使用专用动作。角色编码仅有普通新增许可，角色状态/数据范围、关系集合、部门父链及菜单注册字段不提供普通修改许可；专用动作仍必须经过各自事务所有者的委派和完整锁计划检查。

`project_relation_cell()` 在可信所有者提供的同租户关系目标上，分别使用主记录和源记录的适用角色求值。用户关系字段与实际角色/部门来源均允许读取后，才产生安全单元格及两侧 `SourceRef`。源记录 ID、对象或租户不匹配即拒绝；隐藏单元格不携带正文或来源。角色国际化名称同时依赖角色名称许可，不能恢复隐藏名称。派生字段只声明来源，不是独立授权项；完整数组对齐、树重建和批量取数仍由业务适配器负责。

System、菜单配置及角色 Agent 绑定写者在既有完整事务计划内检查候选对象状态。通用 head 出现后，相关写入必须使用匹配目录的 sealed active manifest；准备、冻结或摘要不匹配均失败关闭。角色/菜单按租户内角色集合求值，部门和用户仍按每个角色独立的记录范围求值。字段检查以实际提交和默认写足迹为准，包含子按钮名称及菜单改名导致的 i18n 清理；同值、显式 null 和不可读但可写字段分别处理。用户本人资料保留固定最小本人操作和显式拒绝优先，旧导入/导出交付入口继续拒绝通用 head。

菜单更新为严格可选字段输入，拒绝空对象、未知字段、重复按钮代码和不可空字段的显式 null。路由/按钮注册及角色定义/关系变更还须通过原专用委派校验；菜单父节点、全部后代绑定角色和成员的影响不能省略。普通字段许可不授予注册或委派权。写入响应在通用模式只返回固定结果或 ID，业务读取仍须使用受保护投影。

## 查询范围证明

`query_counterexample` 返回 `base_scope AND NOT(permission_coverage)`。每个依赖的覆盖范围为各角色允许范围并集减去拒绝范围并集，再对全部依赖取交集。SQL NULL 视为不在该角色范围，避免三值逻辑遗漏无权记录。表达式使用现有严格会话支持的布尔操作，不增加 SQL 函数白名单。

所有者应先在完整业务基础范围执行 `EXISTS` 或 `LIMIT 1` 检查，再应用客户端筛选、排序和分页。基础范围必须含可信租户边界；这里的 SQL 表达式由服务器构造，不能从请求条件充当权限证明。`role_scopes` 必须覆盖上下文角色集；调用查询证明时，该集合表示待检查的角色，逐记录求值时则只保留对该记录适用的角色。

该辅助函数只处理单个对象的显式查询依赖；跨对象关联须由所有者分别证明，不能因对象 A 的筛选许可获得对象 B 的字段许可。

## 来源传播

`SourceRef` 固定域、租户、具体记录、字段、用途、目录摘要和投影版本；固定域必须无租户 ID。`SourceNode` 记录本节点引用及父节点。`collect_sources` 检查所有输入节点可达、无环、有界、摘要/版本一致及租户一致，每个副本必须在自身祖先闭包中包含静态依赖，不能借用无关兄弟节点的证据。同对象依赖必须对应同一记录。

跨对象依赖记录之间的真实关联仍由可信所有者提供并复验。来源闭包只表示证据完整性，不能生成授权规则，也不能使历史正文在撤权后继续可见。实际交付前必须用当前身份、原始用途和当前策略逐项复验；未知或不完整来源应拒绝交付原值。

## 预算和兼容接口

| 项目 | 上限 |
| --- | --- |
| 目录 | 64 对象，每对象 256 字段；512 动作，每动作 256 用途；规范化 1 MiB |
| 静态来源依赖 | 4096 边，深度 16 |
| 规则编译 | 总计 262144 条、64 MiB；每租户/角色/对象最多 2048 条、256 KiB，可收紧 |
| 角色上下文与查询 | 4096 角色，单对象 256 查询依赖 |
| 投影 | 256 字段，1 MiB 逻辑编码、16384 节点、嵌套深度 8 |
| 来源图 | 节点与原始 refs 各 16384，65536 边，深度 16，规范化 4 MiB |
| 来源闭包展开 | 累计 262144 条；父闭包合并累计处理 1048576 条 |

这些是逻辑输入与展开预算，不是进程内存硬限制或 CPU 抢占。输入超限返回 `AUTHORIZATION_PLAN_LIMIT_EXCEEDED`；非法契约返回 `FIELD_POLICY_INVALID`；功能/字段无权返回 `FIELD_POLICY_DENIED`。错误不包含原始字段值。

[user-fields/1 转换器](../app/modules/system/field_policy/generic_compat.py) 显式保留旧目录支持的操作/用途，先执行原文档每角色 256 条/64 KiB 校验，再展开旧查询中已存在的筛选/关联用途；泛化传输预算为每角色 512 条/256 KiB。转换不会产生排序许可或新增生产接线。列表/详情的现有强制脱敏需由接入方在 `ActionSpec.read_caps` 中声明；转换器本身不识别请求入口，不改变原入口行为。

资源锁目录中 `DICT_TYPE` 位于 `740`，`FILE` 位于 `745`，二者同 ID 时仍有唯一顺序。该顺序适用于同一版本的完整事务计划；升级须遵守既有维护停写流程，不能用不同锁序的旧、新进程混跑来替代升级验收。
