# 数据库迁移与发布

本文面向部署维护人员和迁移开发者，说明系统数据库的升级兼容范围、数据处理、回滚限制与迁移发布约束。

## 支持范围

当前 head 以本版本 `alembic heads` 输出为准，完整链见 [迁移目录](../alembic/versions)。

- 空数据库从基线安装；已有数据库的结构迁移支持从 `v0.1.4` 发布边界 `bf244f9a8b76`，或同链已发布节点 `d01010100101`（含 `v0.1.6`）继续升级。通过 `alembic current` 与对应发布产物核对来源。
- 早于该边界的已发布数据库，应先使用相应旧版本代码升级到 `bf244f9a8b76`，再切换到当前版本。
- 曾运行被压缩的开发迁移的数据库不在自动升级范围。必须核对结构和数据，选择备份后重建或经审查的专项转换；不能仅修改版本号。
- 执行升级前备份数据库并运行 `alembic current`，确认版本属于上述支持路径。不要对用户数据库执行未经验证的 `stamp head`。

结构迁移范围不代表完整目标版本的应用组合、配置及业务入口已通过升级验收；部署还须核对该版本的正式发布清单与兼容说明。

## 安装与升级

用户使用 hohu-cli 自动编排迁移与初始化。以下命令供维护人员在已备份、已核对目标数据库的环境中诊断，不是用户额外必做的手工步骤。

```bash
alembic current
alembic heads
alembic upgrade head
alembic current
```

迁移失败时，初始化必须停止，不得继续执行种子脚本或通过 `stamp head` 跳过失败。排除故障并确认数据库状态后，再执行升级与初始化。

## 升级中的数据处理

从受支持的发布边界升级时，迁移同时处理已有数据：

- 为已启用模型建立默认租户的模型授权策略，按 `sort_order`、`model_id` 确定默认模型；停用模型不授予默认租户使用权限。
- 建立父菜单外键前，将根菜单的父节点值从 `0` 转为 `NULL`。
- 为能够确定用户归属的历史登录记录回填租户；无法确定归属的记录保留 `unresolved` 审计范围。
- 将内置设置从 `sys_config` 搬迁至租户隔离的 `sys_setting`，自定义参数保留在原表；默认设置由初始化补缺，不覆盖部署方已有值。
- 建立系统级邮件配置和邮箱验证记录。账号自助服务迁移将 `register_enabled` 设为 `false`；既有邮箱不自动获得验证状态，更改邮箱会清除原验证信任。升级后按部署政策配置邮件服务并显式启用注册或找回密码。

迁移还维护平台审计追加限制、审计关联验证、平台主体和租户的安全版本触发器，以及邮箱变更时的验证信任失效保护。SQLAlchemy 的结构自动对比不会自动生成这些保护；维护或合并迁移时必须保留相应 SQL 和数据转换。

## 用户字段策略候选存储

追加迁移 `e0202a000001` 接在 `d01010100101` 之后，建立全局授权 guard、租户策略状态、不可变修订、角色候选绑定和追加审计五张表。已有租户及后续新租户均建立 `legacy` 初始状态。迁移不生成角色策略、不改变既有业务授权；内部候选只能处于 `legacy` 或 `ready`，`ready` 也不表示策略已生效。当前没有公开管理接口或激活入口。

策略修订和审计不可修改或删除；候选绑定通过归档保留版本及引用。租户状态不能删除，存在策略历史的角色受外键保护，不能硬删除。迁移没有自动给旧角色绑定策略，未产生策略历史的旧角色仍按原有规则管理。全局或租户状态缺失时，内部策略服务拒绝操作，不自动补行或退回默认允许。

此结构迁移是字段权限能力的存储前置。完整授权写者、业务入口和客户端接入仍未开放，不能据此判断一个部署已启用字段权限或已完成整个目标版本的升级验收。

## 回滚

回滚前停止写入并备份数据。迁移的 downgrade 会移除新表或新字段，不能代替数据恢复；优先使用经过演练的数据库备份与匹配的应用版本恢复。隔离测试中空库的 downgrade 成功，不表示带业务数据的降级是无损的。

`e0202a000001` 仅允许在无策略修订、绑定及审计，且全部状态和全局 guard 均保持初始值时降级。产生候选历史或状态推进后会明确拒绝降级；不得删除历史或重置版本来绕过检查，应使用匹配的备份与应用版本恢复。

## 发布规则

1. 开发分支内尚未发布的迁移可以合并；发布后的迁移冻结，后续修复追加新迁移。
2. 每个版本尽量保持少量职责明确的迁移，不以文件数量替代升级正确性。
3. 发布前验证空库安装、受支持版本升级、数据修复及数据库安全保护；记录唯一 head。
4. 不提交实验数据库快照、备份迁移目录、临时操作脚本或本地凭据。
