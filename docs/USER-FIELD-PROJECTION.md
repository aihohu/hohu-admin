# 用户查询与字段输出契约

本文适用于产品与 Backend/Web 0.2.0 开发分支。字段策略默认未启用；`legacy` / `ready` 不应用候选规则。管理员必须通过当前构建的部署资格检查，再显式激活租户策略。业务请求不能指定策略模式、角色授予或绕过字段授权。

## 策略管理与启用

角色页面的“用户字段策略”抽屉提供静态字段/操作/用途选项、规则差异及不含业务字段值的有效能力样本。样本最多覆盖当前角色的5位启用成员、每位20条记录，使用各角色自己的记录范围；截断会明确提示。样本不替代完整查询范围证明。用户修改规则后必须重新预览，发布必须填写理由；版本冲突或提交结果未知后只能重新加载核对，不能自动重提。

控制面路径为 `/system/user-field-policy/{role_id}`：GET读取，POST后缀`preview`、`publish`、`ready`、`activate`、`freeze`。读取/预览要求当前租户启用的`R_SUPER`及显式`system:user:field-policy-view`，发布/待激活要求`field-policy-edit`，激活/冻结要求`field-policy-activate`；这些均使用完整`system:user:`前缀。超管业务字段没有隐式授予。

三项管理权限位于角色管理菜单下。新建安装和新引导的托管租户将其授予初始管理员；已有环境同步菜单后，需要通过既有角色菜单授权入口显式授予。迁移不会自动扩张已有角色的管理权限。

发布携带`expectedVersion`、`catalogDigest`、`rules`、`reason`；预览省略理由。规则字段ID使用目录中的snake_case稳定名称；不接收任意表达式或通配符。状态转换携带`expectedEpoch`、`expectedManifestDigest`、`reason`。响应使用统一信封、字符串ID，包含当前修订、状态及激活阻断原因。

状态为`legacy → ready → enforcing`。激活、规则发布与冻结的审计、摘要和epoch变化在同一事务提交；enforcing发布立即更新生效策略。`frozen`拒绝受保护业务读取和变更，保留最小认证及受权策略修复；修复后重新核验再激活。首次激活后数据库禁止回到legacy/ready；降级迁移也拒绝有激活事实的数据库。关闭部署开关不会恢复原文字段。

`USER_FIELD_POLICY_AVAILABLE`默认false。激活还要求`USER_FIELD_POLICY_QUALIFICATION_FILE`指向部署方维护的只读JSON资格记录（最大32KiB），绑定`RELEASE_BUILD_SHA`、目录与当前适配器源码摘要，以及入口和客户端验收结果。记录不是浏览器参数、授权令牌或停写证明；缺失、变更或不匹配返回`FIELD_POLICY_ACTIVATION_BLOCKED`。直接启动与Docker Compose使用相同配置，Compose挂载该文件即可，不要求新部署平台。

资格记录schema为1，固定字段为`schema`、`build`、`catalogDigest`、`adapterDigest`、`surfaces`、`clients`、`evidenceDigest`、`localCandidate`。surfaces包括rest/auth/relations/query/transfer/ai/history/old-web/concurrency，均须为passed；clients包括web/app/desktop/cli，每项包含完整Git build和status，Web必须passed，其他客户端仅在确无用户管理入口时可声明no-user-management-surface。evidenceDigest引用部署方保存的验收材料SHA256；adapterDigest由后端`qualification.adapter_digest()`计算。localCandidate必须为布尔值，生产环境拒绝本地候选资格。该记录是部署方声明，不自动证明测试真实执行；资格必须根据实际支持入口验收，不能据此豁免缺失测试。

## AI 字段与上下文

AI 用户查询在过滤、歧义计数和聚合前检查完整基础范围的字段依赖。列表及查找的模型结果、UI、关系集合、审计摘要和标签参数使用同一记录的字段决定，既有工具列白名单继续作为上限。用户修改保留原有 `None=未修改` 语义；部门/角色调整检查关系根。写入预演、确认持久化和执行分别复验；无法展示必要目标身份或完整变更影响时返回 `FIELD_CONFIRMATION_FACTS_REQUIRED`，需要重新选择可验证的操作。

新 AI source、确认和操作日志保留内部字段来源；assistant 继承原 source 的来源，不在恢复时换成当前授权。旧记录不回填。仅从未启用的legacy/ready可兼容缺来源记录；enforcing必须核验当前活动策略、原始来源和授权水位。

同一回复合并多个已验证来源时，未依赖数据范围的来源不会覆盖其他来源的范围摘要；任一非空摘要继续约束整条回复及后续历史读取。已保存的回复与后续流式结束结果合并时也遵循相同规则，不因保存顺序丢失范围约束。不同的非空范围摘要或不同 Agent 不能合并，每个来源仍独立复验当前授权。

每轮模型请求、后续工具和每段流式输出发送前重新核验身份及字段依赖。目录、授权水位或构建改变后停止原 run，返回 `FIELD_AUTHORIZATION_CHANGED`，用户需重新发起对话。自然语言采用保守的完整用户字段依赖，因此部分变化也可能使整个旧回答不可见。已经放行的字节无法追回；模型和网络 IO 期间不持数据库锁。成功及未知的执行事实继续由原完成协议判定，不因正文不可见而改成失败或自动重做。

查询回放缓存先读取 Redis，再在独立数据库授权事务内检查当前权限和来源；TTL 不替代撤权检查。当前字段证据还绑定结果下载令牌。无法证明的正文不返回，原审计记录保持不变。激活、冻结或修订改变后，旧确认、运行及下载需要重新发起或生成。

## 读事务与输出

用户列表、本人资料、认证头像与邮箱、部门成员及租户审计列表在专用读事务中重验身份和原有功能权限。普通读事务持有全局与租户共享授权屏障，审计列表从进场即持租户独占屏障，直到查询和DTO投影完成；授权写者必须等待屏障释放。活动加载器核验完整绑定清单和不可变修订摘要；缺失、畸形、目录不匹配或部署关闭均失败关闭，不回退到兼容授予。

用户 DTO 使用显式字段来源，不返回 ORM 对象图。ID 为字符串；字段不可读时省略键，数据库实际空值保留为 `null`。列表手机号、邮箱继续遵循掩码上限。角色及部门名称、ID 和关系标记随对应关系字段整体投影，不能通过标签绕过字段决定。

`fieldAccess` 只包含能力信息：`read`、`maskId`、`create`、`update`、`replace` 和 `queryOps`。它不携带字段值，也不是写入授权凭据。界面可据此显示操作，但服务端仍重新验证权限。列表元数据受原有功能权限约束；本人账户更新能力仅作用于当前账户。

`GET /system/user/field-capabilities` 返回本人资料的字段能力。认证最小身份继续返回 `userId`、`userName`、`roles`、`buttons`、`isSystemAdmin`；头像单独投影，不将最小身份扩展为任意个人信息查询。

列表固定按创建时间倒序，再按用户 ID 倒序，最多每页 100 条。注册查询计划声明过滤、角色关系条件和固定排序依赖；字段查询证明检查施加客户端过滤和分页前的完整基础记录范围。缺少查询授权时整个请求返回 `FIELD_QUERY_DENIED`，不能先缩小结果或 total 再验证。记录权限仍由服务器按租户和数据范围解析。

## 部分更新

`PATCH /system/user/{user_id}` 使用原 `system:user:edit` 权限及写事务入口：

- 未携带字段保持原值；可空字段显式 `null` 表示清空。
- 用户名和状态允许省略，但不接受显式 `null`；空请求拒绝。
- 未知字段、同一字段同时使用 snake_case 与 camelCase、密码或关系字段混写均拒绝。
- 手机号、邮箱的掩码占位符返回 `FIELD_MASKED_INPUT_INVALID`，必须填写新值或省略。

原 `PUT /system/user/{user_id}` 继续要求用户名和状态。携带的字段即使值未变化，也纳入字段写入检查。密码与完整角色/部门关系替换继续使用各自接口。AI 工具既有 `None` 表示未修改的语义不变。

## 身份副本与开放边界

legacy/ready审计列表保留原历史用户名和日志事实。enforcing下相同入口按稳定tenant/user ID和字段来源检查当前可见性，没有客户端模式开关。审计适配器预先取得全局共享屏障与租户独占屏障，阻止审计追加在来源覆盖证明与筛选、计数之间插入新记录；不能在查询途中升级锁。

操作日志的历史用户名可关联到原用户字段，但当前用户缺失或不在可见范围时，严格投影省略副本。登录输入可能是用户名或邮箱，只有 user ID 无法证明其字段来源；自由文本参数和消息也没有逐字段来源，严格投影整体省略这些值，不按文本猜测身份。历史数据库事实不被改写。

AI历史、复制来源和文件使用当前授权及来源水位复验。未具备来源证明的结果不能作为活动策略下的正文交付；内部旧兼容服务保留拒绝激活状态的检查。

Web用户编辑仅提交实际修改且可写的字段；掩码与替换输入分开，空白替换默认不修改，可空字段有明确清空操作。关系未完整加载或缺替换能力时禁止回写。旧Web的PUT同样在服务端检查全部携带字段，客户端版本Header不影响授权。错误文件通过带Bearer的服务请求下载，不直接打开返回的裸地址。

## 导入、导出与文件下载

导入解析保留实际提供的列，拒绝未知表头和重复别名；空列不会当作未提供。导入前声明用户名与工号匹配、携带字段、默认性别/状态及角色/部门关系写入要求，整批检查在创建持久预览或执行首行写入之前完成。覆盖仍保留既有语义：空资料不清空，性别和状态采用默认值；员工同步模式和冲突策略在预览后不能更改。改变模式后应重新预览。

导出最多5000行，固定按用户ID排序，查询证明先于筛选和行数限制。字段投影取export与management.read的交集；脱敏值进入工作簿，全部不可见的列省略，部分不可见的单元格显示“未授权”。部门路径和角色编码随关系根一起裁剪；用户文本作为Excel文本保存。

新文件保存独立内部字段来源，包括租户、操作人、来源对象、字段等级或写入要求、策略水位、目录/构建版本和文件摘要。元数据接口不返回该来源记录。下载重验当前身份、功能、对象/字段权限、来源水位和文件内容；无法证明时返回`FIELD_TRANSFER_REGENERATE_REQUIRED`，应重新生成。旧无来源资产仅在显式legacy/ready兼容路径保留原下载行为；严格适配器拒绝。文件来源不替代AI执行完成证明和签名下载令牌。

`GET /system/file/import-error/{batch_id}.xlsx` 使用Bearer身份和`system:user:import`权限，仅下载本人批次的错误文件。REST导入和批次详情的`failedRowsFile`返回此地址；文件包含行号、字段、稳定错误码和静态说明，不复制失败原值。预览源有效期10分钟，错误附件为完成后24小时，导出文件30天；响应禁止缓存。

模板、批次/日志、导出任务读取在共享屏障内形成DTO或完整文件。模板部门来自当前可访问范围，角色来自当前可授予范围；隐藏字典也遵循相同约束。普通用户仅能查看本人批次/任务，超管可跨操作人查看。操作人名称依据当前用户ID和字段权限投影；不明来源的日志正文、筛选快照、理由与错误自由文本不返回，文件名统一显示为`users.xlsx`。历史审计事实保持不变。
