# 需求与范围

本指南供功能提案和 PR 评审使用。应用功能以当前代码和正式手册为准；设计提案不等于交付承诺。

## 一个提案需要回答的问题

| 问题 | 应提供的信息 |
| --- | --- |
| 谁遇到了什么问题？ | 具体角色、操作场景、现有行为及影响 |
| 改完后如何使用？ | 入口、主要流程、成功与失败反馈 |
| 哪些不在本次范围？ | 明确非目标，避免顺带建设未经验证的通用平台 |
| 谁可以操作哪些数据？ | 系统管理员、租户管理员、普通用户及跨租户限制 |
| 如何与既有安装共存？ | 数据迁移、配置归属、CLI 与客户端配套变化 |
| 如何判断完成？ | 可复现的验收条件、拒绝路径、回归测试 |

固定文案使用语言资源，用户输入保留原文。产品设置与部署配置分开，遵循 [系统设置](SYSTEM-SETTINGS.md)。操作应有清晰的空态、加载、错误和权限反馈；前端隐藏入口不能代替后端授权。

优先交付完整可用的流程。涉及新表、权限范围、状态机、并发和 API 契约时，先明确这些边界，再进入实现。

## 资料交付

原始调研、草案和计划按 [文档维护规则](DOCUMENTATION.md) 保存。对外手册说明当前使用方法与限制，不粘贴任务清单、聊天结论或一次性测试成绩。重大取舍默认由内部 ADR 保存，影响使用、扩展或升级的稳定理由整理进正式手册；具体实现流程见 [开发指南](DEV-GUIDELINES.md)。
